# Court Night build log

Times are Europe/London (UTC+0 on 26 Oct 2026), taken with `date`. Issue 2 of Sport Builds. Prompts are kept by the Builder outside this repo.

- **Start: 18:54**, Mon 26 Oct 2026. Read the research note (tool #1) and the planner and site conventions: plain ES modules, no framework, strict CSP in `_headers`, Cloudflare Pages direct upload, fonts self-hosted from the site repo (Barlow Condensed 800 and Inter, SIL OFL).
- **Step 1, scheduler, standings, validation, share, storage and tests: 18:55 to 18:58.** Pure ES modules with no DOM so Node can test them. Americano: per round a seeded local search (40 restarts, swap players between slots) minimises repeated partners (weight 30 per repeat squared), repeated opponents (8) and repeated court numbers (1). Sit-outs: fewest sit-outs so far, then most games played, then sat out longest ago, then list order. Mexicano: round 1 is an Americano round; later rounds rank the playing players by standings, top four on court 1, and inside a group 1st+4th v 2nd+3rd unless that repeats a partnership. First run: 8 players over 7 rounds gives all 28 partner pairs exactly once, and 24 players on 6 courts never repeat a partner.
  - What broke: my own first versions of three standings tests had wrong expectations (alphabetical order, an incomplete score not counting towards progress, and some leftover scratch lines). I rewrote those tests rather than the code.
- **Step 2, UI (index.html, style.css, app.js, card.js, _headers, tools): 18:58 to 19:01.** Plain DOM built with a small helper using textContent only (no innerHTML), so names cannot inject markup. Score inputs update only the standings and the match message rather than rebuilding the page, so the keypad stays open while typing. Score quick entry: typing one side fills the other as points minus the score, tracked with an `auto` flag so a hand-edited value is never overwritten. Mexicano rounds are made on demand by a "Make round N" button.
- **Step 3, browser checks, README, tests green: 19:00 to 19:05.** `tools/screenshots.mjs` drives headless Chrome at 360px through a whole night (paste a list, duplicate name rejected, custom points, quick entry, validation, reload keeps the night, late arrival, correcting an earlier round, share link opened in a fresh browser profile, new night with confirm, Mexicano one-round-at-a-time) and fails on any console message or any request to another origin. 65 Node tests pass.
  - What broke, and the fix: (1) my tiny static server returned 404 for everything because of a bad path-prefix check; fixed with resolve(). (2) The score quick entry did not re-balance when correcting a score that had been typed by hand (17 and 11 -> changing 17 to 20 left 11, adding up to 31). Fixed: if the two scores already added up to the points per match, correcting one side re-balances the other. A mismatch the user entered on purpose is left alone and flagged. (3) The star after the leader's name rendered as a colour emoji; removed in favour of the gold rank badge. (4) The legend spacing in the setup form was cramped; fixed. (5) Several of my own test expectations were wrong rather than the app (see step 1).
  - Scope: kept everything in the brief. Not done: re-pairing Mexicano rounds that are already made when an earlier score is corrected (it would move people who have already played); instead the standings update immediately and "Re-make unscored rounds" re-pairs the rounds that have no scores. Live multi-device sync stays a documented next step.
- **Step 4, GitHub repo, Cloudflare Pages deploy, custom domain: 19:05 to 19:07.** Public repo norris1976/court-night created and pushed (commit as Tim Norris). Pages project `court-night` created (direct upload, production branch main) and deployed with wrangler 4.86.0. On https://court-night.pages.dev: 200, strict CSP, nosniff, no-referrer, HSTS, `Cache-Control: ... no-transform`, no Set-Cookie, no Web Analytics beacon in the HTML, and the full browser check script passes against the live URL (no console messages, no requests to another origin).
  - What broke: the first run of the browser checks against the live URL, seconds after the deploy, failed once; the same run passed on the next try (it looked like the deployment settling). Not investigated further.
  - **Blocked: the DNS record.** The Pages custom domain `court.sportbuilds.co` was added through the API (status "pending"), but the Cloudflare token in the environment cannot see the sportbuilds.co zone (the zone list for it only contains another account's domain), so the proxied CNAME `court` -> `court-night.pages.dev` was not created. It needs to be added by hand in the dashboard (DNS > Records), or with a token that has Zone > DNS > Edit on sportbuilds.co. I did not try other credentials.
